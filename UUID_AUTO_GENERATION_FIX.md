# UUID Auto-Generation Fix - QR-Based ERP System

## Issue Summary

**Error**: `invalid input syntax for type uuid: ""`

**Root Cause**: The bulk import functionality was generating UUIDs and sending them to Supabase, but Supabase auto-generates UUIDs for the `id` field. This caused conflicts when empty or invalid UUID values were sent.

## Problem Details

### Database Auto-Generation vs Manual Generation

**Supabase Database**:
- Auto-generates UUIDs for the `id` field
- Auto-generates timestamps for `created_at` field
- Should not receive pre-generated UUIDs

**Local Storage**:
- Requires manually generated UUIDs
- Requires manually generated timestamps
- Needs pre-generated UUIDs for offline functionality

### The Conflict

The import processing was:
1. **Always generating UUIDs** regardless of data source (Supabase vs Local Storage)
2. **Sending UUIDs to Supabase** which expects to auto-generate them
3. **Sending empty UUIDs** when the generation failed, causing the error

## Solution Applied

### 1. Conditional UUID Generation

**File**: `src/components/registration/RegistrationForm.tsx`

**Before (Problematic)**:
```typescript
const processedEmployees = importedData.map(item => {
  const employeeId = item.id || crypto.randomUUID(); // Always generate UUID
  return {
    id: employeeId, // Always include id
    qrCode: item.qr_code || item.qrCode || employeeId, // Always include qrCode
    // ... other fields
  } as Employee;
});
```

**After (Fixed)**:
```typescript
const processedEmployees = importedData.map(item => {
  // For Supabase, don't generate UUIDs - let the database auto-generate them
  const employeeId = useSupabase ? undefined : (item.id || crypto.randomUUID());
  return {
    ...(useSupabase ? {} : { id: employeeId }), // Only include id for local storage
    ...(useSupabase ? {} : { qrCode: item.qr_code || item.qrCode || employeeId }), // Only include qrCode for local storage
    // ... other fields
  } as Employee;
});
```

### 2. Updated Supabase Field Mapping

**File**: `src/utils/supabaseRegistrationService.ts`

**Before (Problematic)**:
```typescript
const supabaseEmployees = employees.map(employee => ({
  ...employee, // This included id and qrCode fields
  qr_code: `EMP-${employee.id}`, // This used the id field
  // ... other mappings
}));
```

**After (Fixed)**:
```typescript
const supabaseEmployees = employees.map(employee => ({
  name: employee.name,
  type: employee.type,
  department: employee.department,
  position: employee.position,
  blood_group: employee.bloodGroup,
  site: employee.site,
  status: employee.status,
  photo: employee.photo,
  email: employee.email,
  phone: employee.phone,
  old_id: employee.oldId,
  company_id: employee.companyId,
  cost_center_code: employee.costCenterCode,
  profit_center_code: employee.profitCenterCode,
  hourly_rate: employee.hourlyRate,
  last_updated: employee.lastUpdated,
  created_at: employee.createdAt
  // Note: No id or qr_code fields - let Supabase auto-generate them
}));
```

### 3. Updated Reverse Mapping

**After (Fixed)**:
```typescript
const transformedData: Employee[] = (data || []).map(employee => ({
  id: employee.id, // Auto-generated by Supabase
  name: employee.name,
  // ... other fields
  qrCode: `EMP-${employee.id}`, // Generate QR code from auto-generated ID
  // ... rest of fields
}));
```
